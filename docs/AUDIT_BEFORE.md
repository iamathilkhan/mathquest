### Trace: `page` → `useLesson` → `/api/lesson` → `lib/llm` → `GeminiLlmClient`
1. `useLesson` checks `localStorage` cache for key `mq:lesson:${realmId}:${subSkillId}:${PROMPT_VERSION}`.
2. If cache miss, sends `POST /api/lesson`.
3. In `app/api/lesson/route.ts`, invokes `getLesson()` in `lib/llm/lesson.ts`.
4. `getLesson` attempts `llm.generateJson()`:
   - When `GEMINI_API_KEY` is missing or models are empty &rarr; throws `LlmUnavailableError("GEMINI_API_KEY or model chain missing")`.
   - On 401/403 &rarr; throws `LlmUnavailableError`.
   - On 404/400 &rarr; tries fallback model; throws `LlmUnavailableError` if all fail.
   - On timeout (>25s) &rarr; throws `LlmTimeoutError`.
   - On invalid math verification &rarr; retries once; if failed, falls through to catch block.
5. In catch block, calls `deps.seed.lessonFor()` and returns `{ source: "seed", lesson }`.
*(Note: degradedReason is currently not returned by the `/api/lesson` endpoint; to be implemented in Stage S2)*.

## Ranked Root Causes: Why Lessons Look Identical & No LLM is Used

1. **No Live API Key**: No `GEMINI_API_KEY` was ever configured in `.env.local`, forcing all lesson and question requests into the local fallback path.
2. **Template-Based Seed Generators**: The fallback seeds were created using procedural string template scripts (`scripts/generate-seed-lessons.ts`) that re-used rigid boilerplate for hooks, big ideas, and vocabulary.
3. **Absence of Sub-Skill Specific Pedagogical Context**: The seed generator lacked detailed curriculum schemas (misconceptions, context stories, grade-level vocabulary) to differentiate the output.
